# Unassigned Seat order-search calibration

The inspected Unassigned Seat page has 106 orders with a 100-row page size. Its MUI grid's complete row model contains all 106 orders. The second page holds the final six orders; searching for one of those order numbers from the first page returns one row and the native footer shows `1–1 of 1`.

The assignment controls form a `.MuiToggleButtonGroup-root` whose buttons read Unassigned, Assigned and All. Their parent is a MUI Grid item, not a flex row. The enhancement temporarily applies a wrapping inline flex layout to that item and inserts its owned search control after the native toggle group. No React-owned element is moved. Turning the enhancement off restores the parent's original inline declarations.

`order-search-main.js` finds the existing MUI API ref in the grid's React context. It reads React's context references but never rewrites React state, props or row data. It matches order numbers and customer names against the complete row model, combines the results with existing filters, then supplies the matching order IDs to MUI's built-in `isAnyOf` filter. This also works with MUI Community's single-filter limitation. Legacy and modern filter argument/model shapes are supported. Native renderers, column configuration, existing filters and sorting are retained; page one is selected after a query change. The `rowsSet` event rebuilds the matching IDs and refreshes counts when assignment views load a new dataset.

`order-search.js` owns `enhancements.searchUnassignedOrders`, disabled by default. Input is debounced by 150 ms. A grid remount reattaches the current query, and a query clear or Escape restores the baseline filter. The DOM event bridge returns counts and capability status only. It does not export row/customer records; queries are not persisted.

Etix can replace its column definitions during a React render, removing a custom operator while leaving an active filter model behind. The adapter therefore uses only the built-in operator and never changes native columns. Active searches survive synchronous column refreshes, including clicking seating links. Automatic row-set refreshes retain the current page. Temporary loading or grid errors retry with a delay capped at two seconds; they no longer become permanently unavailable after five seconds. Successful replies and disabling the enhancement cancel pending retries.

Live checks on 22 November 2026 verified an order from page two, an uppercase partial customer name and clearing back to all 106 orders. Automated fixtures cover modern/legacy grid APIs, complete-model filtering, accents and name word order, baseline filter restoration, no-match recovery, preserved native renderers, changing row sets and refusing server-paginated partial data. Unsupported future grid interfaces leave the native list available.

Version 0.9.25 was checked live after reproducing the missing-operator failure. Partial-name search remained active after clicking its seating link, an order from page two still returned one result, and switching Unassigned → All retained the query and recovered its result. Clearing restored all 106 orders. Regression fixtures now simulate synchronous column replacement and more than five seconds of transient failures before recovery.
